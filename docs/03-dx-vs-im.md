# 歯科 (dx) と 内科/医科 (im) の差分

クローン元を選ぶ・薬科で何を差し替えるかを判断するための差分一覧。

## 1. 一言で言うと

**アプリ骨格・月次締め・ロボットペイメント送信は同型。**  
違うのは主に **DB・`cod` 接頭辞・レセプト取込パーサ・一部補助機能**。

薬科を「本番 dx をクローン」する場合でも、決済振り分けは **im 導入時と同じパターン（接頭辞 + `result.php` 分岐）** を踏む必要がある。

## 2. 設定・識別子

| 項目 | dx（歯科） | im（内科） |
|------|------------|------------|
| 本番 DB | `xs547384_dx` | `xs547384_improd` |
| DEV DB | `xs547384_dxdev` | `xs547384_im` |
| `cod` 接頭辞 | **なし**（デフォルト扱い） | **`im-`** |
| `AID` | `115106`（共通） | 同左 |
| `SERVICETITLE` | `DX クリニックペイメント` | 同左（画面タイトルも歯科表記のまま） |
| `$m_category` | 歯科向け記号定義を含む | 現状ほぼ同内容（医科用に最適化しきれていない可能性） |

## 3. `cod` 生成（本番パス）

**歯科** `dx/class/clsystem.php` → `generateRPdata()`:

```text
{irkkcode}-{original_pid 7桁}-{YYYYMM}-{uniqid}
```

**内科** `im/class/clsystem.php` → `generateRPdata()`:

```text
im-{irkkcode}-{original_pid 7桁}-{YYYYMM}-{uniqid}
```

### 注意（既知の穴）

内科の `generateRPdataDEBUG` / 一部イレギュラー調整パスでは **`im-` が付いていない**箇所がある。  
薬科クローン時は **`generateRPdata` 系すべてで接頭辞を統一**すること。DEBUG 経路を本番相当のキックバックで使うと、歯科 DB に誤振り分けされる。

## 4. コールバック

| ファイル | 挙動 |
|----------|------|
| **`dx/manager/result.php`** | `cod` 先頭 2 文字が `im` → improd DB、それ以外 → dx DB。**本番の共有入口** |
| `im/manager/result.php` | 自環境 `DBNAME` のみ。接頭辞分岐なし |
| `dxdev` / `imdev` の `result.php` | 自環境 DB のみ。**prod のような横断振り分けなし** |

内科の決済結果が正しく反映される前提は「Robot Payment 管理画面のキックバック先が **dx 本番 result.php**」であること。

## 5. レセプト取込

| | dx | im |
|--|----|----|
| 主パーサ | `recept-upload-008.php` | `recept-upload-im.php` + `recept-upload-result-im.php` |
| 介護 | `kaigo-recept-upload-003.php` | 同様に存在 |
| 差分の性質 | 歯科レセプト列位置・UK 等 | 医科列位置・負担割合など。パーサ差分は大きい |

科目追加時、**決済まわりは共通化パターンで足りるが、レセプトは科目専用実装が必須**、という切り分けになる。

## 6. その他の機能差

| 項目 | dx | im |
|------|----|----|
| CSV 手動取込（決済結果系） | `__NOUSE__csv-upload.php`（無効化） | `csv-upload.php`（`cod` 先頭が `im` 以外はスキップ） |
| `clsystem.php` 規模 | 大きめ（介護のみ患者・irkkcode 解決などが厚い） | やや小さめ。氏名欠損スキップ等あり |
| 名寄せ | あり | 生年月日表示など UI 差あり |
| 業務ロジックの「科目らしさ」 | 歯科レセプト + カテゴリ M/N 等 | 医科レセプトパーサが主差分 |

## 7. クローン元の選び方（薬科向け）

依頼方針が「**本番 dx をクローン**」なら、次をセットで実施する。

1. `dx` → `ph`、`dxdev` → `phdev` を複製
2. DB・config を薬科用に変更
3. **`cod` に `ph-` を付与**（dx には接頭辞が無いため、ここを忘れるとコールバックが歯科 DB に落ちる）
4. **`dx/manager/result.php` に `ph` 分岐を追加**（必須）
5. レセプト取込を調剤フォーマット向けに新規／差し替え（歯科パーサのままでは不十分）

内科の実装を参考にすべき点は、主に **接頭辞の付け方**と **CSV 取込の接頭辞フィルタ**。
