# clinic-payment ドキュメント

## この docs の目的

科目（歯科・医科・薬科…）を増やすたびにコードベース全体を再調査しなくてよいよう、**共通の仕組み・差分の置き場・クローン時の必須作業**を記録する。

## なぜ「仕様書」ではないか

今回の目的は「画面仕様・業務要件をゼロから定義する」ことではなく、次の2点である。

1. **手離れしても分かる共通基盤**（特にロボットペイメントの単一コールバック振り分け）
2. **新科目追加時に触る場所の地図とチェックリスト**

そのため文書種別は **アーキテクチャ／展開ガイド** とする。

## 調査時点の前提（2026-07）

- 本番 Web ルート: `dx` / `im` / `ph`
- DEV: `dxdev` / `imdev` / `phdev`
- ロボットペイメントのキックバック URL は **歯科本番の** `dx/manager/result.php` に集約
- 店舗 ID（`AID`）は全環境で同一 `115106`
- 薬科の DB 接続は `{ph,phdev}/class/config.php` が単一の設定源

パスワード・SMTP 認証情報などの秘密情報は本 docs には書かない。
